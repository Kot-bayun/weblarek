# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В ходе анализа макета было установлено: в приложении используются две сущности, которые описывают данные, — товар и покупатель. Их можно описать такими интерфейсами:

#### Интерфейс IProduct
Предназначен для учета товаров, которые будут использоваться в приложении.

#### Интерфейс IBuyer
Предназначен для учета данных покупателя, которые будут использоваться в приложении.

### Модели данных
Работа с данными будет реализвана тремя классами, разделенными между собой по смыслу и зонам ответственности:

#### Класс Catalog
Хранит товары, которые можно купить в приложении.

Конструктор класса теперь принимает объект для генерации событий, соответствующий интерфейсу IEvents.

Поля класса:  
`products: IProduct[]` - хранит массив всех товаров.
`currentProduct: IProduct | null` - хранит товар, выбранный для подробного отображения.

Методы класса:  
`setItems(items: IProduct[]): void` - отвечает за сохранение массива товаров, полученного в параметрах метода и за эмит события 'catalog:change'.
`getItems(): IProduct[]` - отвечает за получение массива товаров из модели. 
`getItemById(id: string): IProduct | undefined` - отвечает за получение одного товара по его id. 
`setItem(item: IProduct): void` - отвечает за сохранение товара для подробного отображения и за эмит события 'item:change'.
`getItem(): IProduct | null` - отвечает за получение товара для подробного отображения. 

#### Класс Cart
Хранит товары, которые пользователь выбрал для покупки.

Конструктор класса теперь принимает объект для генерации событий, соответствующий интерфейсу IEvents.

Поля класса:
`myProducts: IProduct[]` - хранит массив товаров, выбранных покупателем для покупки.

Методы класса:  
`getCartItems(): IProduct[]` - отвечает за получение массива товаров, которые находятся в корзине.
`addToCart(item: IProduct): void` - отвечает за добавление товара, который был получен в параметре, в массив корзины и за эмит события 'basket:changed'.
`deleteFromCart(item: IProduct): void` - отвечает за удаление товара, полученного в параметре, из массива корзины и за эмит события 'basket:changed'.
`cleanCart(): void` - отвечает за очистку корзины и за эмит события 'basket:changed'.
`getTotal(): number` - отвечает за получение стоимости всех товаров в корзине.
`getNumberOfItems(): number` - отвечает за получение количества всех товаров в корзине.
`checkItemById(id: string): IProduct | undefined` - отвечает за проверку наличия товара в корзине по его id, полученного в параметр метода.

#### Класс Buyer
Хранит данные покупателя, которые тот должен указать при оформлении заказа.

Конструктор класса теперь принимает объект для генерации событий, соответствующий интерфейсу IEvents.

Поля класса:
`data: IBuyer | null` - хранит данные, введенные покупателем для покупки.

Методы класса: 
`setData(buyer: IBuyer): void` - отвечает за сохранение данных в модели. В этом методе реализована возможность сохранить только одно значение, не удалив при этом значения других полей, которые уже могут храниться в классе и за эмит события 'buyer:changed'.
`getData(): IBuyer[] | null` - отвечает за получение всех данных покупателя.
`cleanData(): IBuyer | null` - отвечает за очистку данных покупателя  и за эмит события 'buyer:changed'.
`validateData(): {} | undefined` - отвечает за валидацию данных. Поле является валидным, если оно не пустое. Этот метод дает возможность определить не только валидность каждого отдельного поля, но и предоставлять информацию об ошибке, связанной с проверкой конкретного значения.

### Слой коммуникации

#### Класс ApiForServer
Использует композицию, чтобы выполнить запрос на сервер с помощью метода get класса Api и получает с сервера объект с массивом товаров. Отправляет на сервер данные о покупателе и выбранных товарах с помощью метода post класса Api.

Конструктор:
`constructor(api: IApi)` - принимает объект, соответствующий интерфейсу IApi.  

Поля класса:
`api: IApi` - объект, соответствующий интерфейсу IApi. 

Методы класса:  
`doGetRequest(): Promise<ApiDataToServer>` - отвечает за выполнение запроса на сервер с помощью метода get класса Api и получаение с сервера объекта с массивом товаров.
`doPostRequest(order: ApiDataToServer): Promise<ApiDataToServer>` - отвечает за отправку на сервер данных о покупателе и выбранных товарах.

### Cобытия, которые генерируются в приложении
В классе Header генерируется событие 'basket:open' при клике на кнопку корзинки. Открывается модальное окно с контентом класса Basket.

В классе Modal генерируются событие 'modal:open' и 'modal:close'.

В классе Success генерируется событие 'success:click' при клике на кнопку "За новыми покупками!". Модальное окно с контентом класса Success закрывается.

В классе Basket генерируется событие 'order:open' при клике на кнопку "Оформить". Открывается модальное окно с контентом классов форм.

В классе CardPreview генерируется событие 'preview:click'. Открывается первая форма.

В классе Form генерируется событие 'form:change'.
